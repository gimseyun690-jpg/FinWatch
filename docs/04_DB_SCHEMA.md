# FinWatch DB 스키마

상태: V5 마이그레이션까지 구현됨. PostgreSQL과 snake_case를 기준으로 한다.

## 1. 관계 요약

```text
users 1--N watchlists N--1 stocks
users 1--N portfolio_holdings N--1 stocks
users 1--N price_alerts N--1 stocks
stocks 1--N market_prices
stocks 1--N news_articles
news_articles 1--N ai_analyses
users 1--N ai_usage_logs
ai_analyses 1--N ai_usage_logs
```

## 2. 공통 규칙

- PK: `BIGINT GENERATED BY DEFAULT AS IDENTITY`
- 시간: `TIMESTAMPTZ`, UTC 저장
- 금액: `NUMERIC(20, 4)`과 통화 코드
- 비율/비용: 충분한 정밀도의 `NUMERIC`
- 생성·수정 시각: `created_at`, 필요한 테이블에 `updated_at`

## 3. 테이블

### watchlists

| 컬럼 | 타입 | 제약/설명 |
|---|---|---|
| id | BIGINT | PK |
| user_id | BIGINT | FK users, NOT NULL |
| stock_id | BIGINT | FK stocks, NOT NULL |

UNIQUE `(user_id, stock_id)`.
사용자 삭제 시 관심종목도 함께 삭제되며 사용자별 생성일 순 조회 인덱스를 둔다.

### ai_technical_explanations (계획, 미구현)

뉴스 분석과 수명주기·입력 구조가 다르므로 기술지표 해설은 별도 테이블로 저장한다. 원시 OHLCV 배열이나 전체 프롬프트는 저장하지 않는다.

| 컬럼 | 타입 | 제약/설명 |
|---|---|---|
| id | BIGINT | PK |
| stock_id | BIGINT | FK stocks, NOT NULL |
| interval | VARCHAR(10) | MVP는 1D |
| latest_recorded_at | TIMESTAMPTZ | 입력의 마지막 완성 봉 |
| calculation_version | VARCHAR(50) | 기술지표 계산 버전 |
| prompt_version | VARCHAR(50) | AI 해설 프롬프트 버전 |
| input_hash | VARCHAR(64) | 정규화된 기술지표 스냅샷 SHA-256 |
| source | VARCHAR(50) | KIS / DEMO 등 |
| freshness | VARCHAR(20) | FRESH / STALE / DEMO |
| summary_signal | VARCHAR(20) | 서버 결정 BUY / NEUTRAL / SELL |
| summary | TEXT | AI 전체 요약, NOT NULL |
| trend_explanation | TEXT | 추세 설명 |
| momentum_explanation | TEXT | 모멘텀 설명 |
| volatility_explanation | TEXT | 변동성 설명 |
| volume_explanation | TEXT | 거래량 설명 |
| supporting_signals | JSONB | text와 evidenceIds 배열 |
| conflicting_signals | JSONB | text와 evidenceIds 배열 |
| risk_notes | JSONB | 위험·주의 문장 배열 |
| data_limitations | JSONB | DEMO·STALE·입력 한계 배열 |
| evidence | JSONB | 서버 생성 ID·지표·표시값 |
| model_name | VARCHAR(100) | 실제 공급자 모델 |
| input_tokens | INTEGER | 0 이상 |
| output_tokens | INTEGER | 0 이상 |
| estimated_cost | NUMERIC(16, 8) | 원 생성 예상 비용, USD |
| cache_key | VARCHAR(255) | NOT NULL |
| generated_at | TIMESTAMPTZ | NOT NULL |

UNIQUE `(stock_id, interval, latest_recorded_at, calculation_version, input_hash, prompt_version)`, UNIQUE `(cache_key)`. 새 완성 봉, 과거 가격 정정, 계산 버전 또는 프롬프트 변경은 기존 행을 덮어쓰지 않고 새 해설을 만든다.

## 4. Redis 키

| 키 | 값 | TTL |
|---|---|---|
| `ai:news-summary:{newsId}:{contentHash}:{promptVersion}` | AI 요약 응답 JSON | 기본 24시간, 설정 가능 |
| `stock:quote:{market}:{symbol}` | 현재가 JSON | 공급자 갱신주기에 맞춤 |

DB가 원본이고 Redis는 재생성 가능한 캐시로 취급한다.

## 5. 마이그레이션

Flyway를 사용하며 현재 적용 파일은 다음과 같다. 파일명과 책임이 바뀌면 이 목록도 같은 커밋에서 갱신한다.

1. `V1__create_core_tables.sql`: 사용자와 종목
2. `V2__create_market_prices_and_demo_data.sql`: 시장 가격과 종목·가격 데모 데이터
3. `V3__add_demo_history_for_watchlist.sql`: 기술지표 시연용 가격 이력
4. `V4__create_news_and_ai_operations.sql`: 뉴스, AI 분석·사용 로그와 데모 뉴스
5. `V5__create_watchlists.sql`: 사용자별 관심종목
6. `V6__extend_demo_market_price_history.sql`: PostgreSQL 데모 가격 이력 확장
7. `V7__smooth_extended_demo_price_history.sql`: 확장 구간과 기존 가격 이력 연결 보정
8. `V8__add_news_content_source_policies.sql`: 뉴스 출처·권리 메타데이터와 허용 출처 정책
9. `V9__version_ai_analysis_by_content_hash.sql`: 뉴스 최종 URL과 본문 hash별 AI 분석 버전
10. `V10__add_structured_ai_analysis.sql`: 긍정·위험 요인, 근거 구간, 분석 범위와 공급자 호출 수
11. `V11__create_portfolio_holdings.sql`: 사용자별 보유 종목과 평가 입력
12. `V12__create_price_alerts.sql`: 가격 알림 조건, 상태와 마지막 평가 정보

`prompt_templates`, `ai_model_prices`는 논리 설계만 확정된 상태이며 후속 운영 기능에서 별도 마이그레이션으로 추가한다.
