# FinWatch 대회 제출 준비 점검

기준일: 2026-07-15
기준 공지: [한성대학교 제13회 창의융합역량 경진대회 참가자 모집](https://www.hansung.ac.kr/hansung/6172/subview.do?enc=Zm5jdDF8QEB8JTJGYmJzJTJGaGFuc3VuZyUyRjIxMjclMkYyMjE3MTElMkZhcnRjbFZpZXcuZG8lM0Y%3D)

작품소개서 PDF의 초기 목업은 구현 계약으로 사용하지 않는다. 제출·발표 자료는 현재 코드와 실제 화면을 기준으로 다시 만든다.

## 1. 공지 기준

- 1차 작품소개서 40점, 2차 대면 질의응답 60점이다.
- 2차는 창의성·체계성 20, 기능성·완성도 20, 기대효과 10, 발표·질의응답 10점이다.
- 2차 대상자는 PT와 자막을 포함한 5분 이내 MP4 작품소개 영상을 제출해야 한다.
- 수상팀은 A1 패널 포스터를 제출해야 하며 미제출 시 수상이 취소될 수 있다.
- 작품소개서에는 본인 전공 외 융합분야를 하나 이상 명시해야 한다.

## 2. 현재 구현 증적

| 평가 축 | FinWatch 근거 | 제출 전에 고정할 증적 |
|---|---|---|
| 창의성 | 전일 변화 추적, 기술·뉴스·공시 관점 충돌, T/N/D/Q 근거 추적 | 변화 브리핑 한 화면과 근거 drawer 캡처 |
| 체계성 | 공급자 어댑터, canonical 종목 식별, 결정론적 지표 계산, 입력 hash·버전·캐시 | 아키텍처 1장, 데이터 흐름 1장 |
| 기능성 | 검색, 상세 차트, WebSocket, 뉴스·공시, 포트폴리오·알림, 세 AI 기능 | 5분 시연 영상과 핵심 API 응답 |
| 완성도 | 권리 정책, 실패 fallback, 사용자 격리, 비용·실패 로그, PWA·모바일 | 백엔드 108 tests, E2E 5 tests, production build 결과 |
| 기대효과 | 캐시 HIT의 토큰·실제 요청 비용 0, 절감액과 응답시간 표시 | 동일 입력 MISS/HIT 전후 수치 캡처 |
| 융합성 | 소프트웨어·빅데이터 처리 + 금융 기술지표·공시 해석 + AI 운영 비용 | 전공/융합분야 역할을 명시한 슬라이드 |

## 3. 5분 영상 권장 구성

1. 0:00~0:30: 투자정보가 분산되고 AI 결과의 근거·비용이 보이지 않는 문제
2. 0:30~1:00: FinWatch 차별점과 전체 구조
3. 1:00~2:00: 종목 검색 → 상세 캔들·지표·그리기 → 공식 공시
4. 2:00~3:15: 일일 변화 브리핑 → 관점 충돌 → T/N/D/Q 근거 이동
5. 3:15~4:05: 같은 AI 요청 두 번 실행 → MISS/HIT → 비용 0과 절감액
6. 4:05~4:35: 관리자 기능별 호출·토큰·비용·실패 확인
7. 4:35~5:00: 융합성, 기대효과, 한계와 확장 계획

화면 전환마다 자막으로 `문제`, `서버 계산`, `검증 근거`, `캐시 절감`, `관리 지표`를 표시한다. 실시간 시장 개장 여부에 의존하지 않도록 핵심 평가는 완성 일봉과 저장된 공식 자료로 시연한다.

## 4. 제출 전 반드시 보완

1. 실제 구현 화면으로 작품소개서와 발표자료를 다시 캡처한다. 초기 목업·placeholder·예시 수치를 최종 증적으로 사용하지 않는다.
2. 동일 요청의 첫 MISS와 두 번째 HIT를 깨끗한 DB/cache에서 촬영하고 관리자 집계가 같은 숫자인지 확인한다.
3. Gemini 무료 quota, KIS 장 상태, Open DART·Naver·Finnhub 호출 실패를 각각 한 번 연습한다. 장애 시 기존 차트·목록이 유지되는지도 보여준다.
4. Finnhub 무료 등급에서는 Forex rate/candle 권한이 없을 수 있다. LIVE USD/KRW 대체 공급자를 정하지 못하면 환율은 DEMO임을 영상과 발표에서 명확히 밝힌다.
5. 발표용 계정·종목·버튼 순서·브라우저 배율을 고정하고 API 키나 환경변수 창은 영상에 노출하지 않는다.
6. 금융서비스가 아니라 정보 정리 도구라는 면책, 출처·기준시각·DEMO/STALE 표시를 화면에서 확인한다.
7. 예상 비용 절감은 공급자 청구액이 아니라 설정 단가와 사용 로그 기반 추정치임을 설명한다.

## 5. 예상 질의응답

- 왜 일반 주식 앱과 다른가: 추천 순위가 아니라 전일 변화, 공식 공시, 관점 충돌과 근거 추적에 집중한다.
- AI 환각을 어떻게 줄였나: 서버가 수치·관점 상태를 먼저 계산하고 Gemini는 존재하는 evidence ID만 설명한다.
- 비용 절감이 실제인가: cacheKey, DB 복구, single-flight로 중복 호출을 막고 HIT의 토큰·실제 요청 비용을 0으로 로그에 기록한다.
- 뉴스 저작권은 어떻게 처리하나: 허용된 권리 프로필만 본문 분석하며 나머지는 메타데이터와 원문 링크만 제공한다.
- 실시간 데이터 장애 시 어떻게 되나: LIVE를 DEMO로 위장하지 않고 마지막 검증값·STALE 또는 명확한 오류를 제공한다.
- 수익률을 예측하나: 미래 수익률·목표주가·매매 명령은 생성·저장 검증에서 차단한다.

## 6. 현재 범위 밖

- AWS 운영 배포, 다중 인스턴스 Redis 분산 카운터·락, RDS 복구 훈련
- 실제 매매·계좌 연동·개인화 투자 자문
- 운영자용 프롬프트 무중단 편집과 모델 단가 이력 테이블

대회 시연은 로컬 단일 서버에서 재현 가능하며, 위 항목은 현재 기능의 완성도와 구분해 확장 계획으로 설명한다.
