# FinWatch UI 폴리싱·제품 디테일 명세

상태: Draft v0.1 — 구현 전 계약

기준일: 2026-07-17

대상: React PWA 앱 셸, 로그인, 대시보드, 종목 상세, 차트, 뉴스·공시, AI 분석, 사용자·관리자 화면

## 1. 목적

FinWatch는 검색, 차트, 기술지표, 뉴스·공시, AI 해설, 포트폴리오, 알림, 관리자 비용 지표까지 대회 MVP 기능을 갖췄다. 이 문서는 기능을 더 늘리기보다 화면의 일관성, 데이터 신뢰도, 상태 표현, 반응형 사용성과 시연 완성도를 실제 금융 정보 서비스 수준으로 끌어올리는 규칙을 고정한다.

핵심 목표는 다음과 같다.

1. 어떤 화면에서도 동일한 디자인 언어를 사용한다.
2. 가격·뉴스·공시·환율·AI 결과의 출처와 기준 시각을 사용자가 즉시 확인한다.
3. loading, empty, partial, stale, error, offline 상태가 정상 데이터와 혼동되지 않는다.
4. 기술적 분석과 AI 결과가 복잡해도 정보 우선순위가 명확하다.
5. 데스크톱, 390px 모바일, 설치형 PWA에서 핵심 시연 흐름이 끊기지 않는다.
6. 제출 영상과 포트폴리오 캡처가 실제 구현을 정확하게 증명한다.

이 문서는 `17_NAVIGATION_AND_CONTENT_LIST_SPEC.md`의 정보 구조를 변경하지 않고 시각·상호작용 품질을 보강한다.

## 2. 범위와 제외 범위

### 2.1 포함 범위

- 공통 디자인 토큰과 컴포넌트 상태
- 일관된 아이콘 체계
- 타이포그래피, 간격, 정렬, 카드 계층
- 데이터 출처·신선도·장 상태·DEMO/STALE 표기
- 차트 툴바, 지표 범례, 축, tooltip, 모바일 조작
- AI 결과의 결론·근거·한계·캐시 상태 표현
- loading, empty, partial, error, offline 화면
- 접근성, 키보드, screen reader 이름, focus 상태
- 데스크톱·태블릿·390px 모바일·PWA 검수
- 성능 체감과 레이아웃 안정성
- 대회 영상·포트폴리오용 화면 증적

### 2.2 제외 범위

- 새로운 금융 데이터 공급자 추가
- 실제 매매·계좌 연동·자동 주문
- 카카오 로그인과 공개 사용자 가입
- AWS 운영 배포
- 기존 API 계산식, AI 프롬프트 정책, DB 스키마의 임의 변경
- 개인화 투자 추천, 목표주가, 수익률 예측
- 전체 디자인 프레임워크 교체
- 기능 수를 늘리기 위한 신규 메뉴 추가

제외 항목은 현재 화면 품질과 인수 조건이 완료된 뒤 별도 명세로 결정한다.

## 3. 제품 디자인 원칙

### 3.1 정보 우선순위

모든 주요 화면은 아래 순서로 정보를 배치한다.

```text
현재 대상과 핵심 수치
→ 변화와 상태
→ 해석
→ 근거와 출처
→ 상세 조작
→ 면책과 한계
```

- 한 카드 안에서 강조 수치는 원칙적으로 하나만 둔다.
- 같은 중요도의 정보에 서로 다른 색상·크기를 사용하지 않는다.
- 영문 eyebrow는 섹션 분류가 필요할 때만 사용하고 한글 제목을 대체하지 않는다.
- 장식보다 데이터와 조작의 의미가 먼저 읽혀야 한다.

### 3.2 금융 서비스 톤

- 배경은 저채도 네이비·차콜 계열을 유지한다.
- cyan/green은 핵심 조작, 연결, 정상 상태에 제한한다.
- 상승과 하락 색상은 시장별 관습을 UI 전역에서 하나의 규칙으로 고정한다.
- 밝은 네온, 과도한 glow, 입체 bevel과 여러 방향의 그림자를 사용하지 않는다.
- 경고색은 실제 경고·지연·데이터 부족에만 사용한다.
- AI 결과를 가격보다 더 강하게 강조하지 않는다.

### 3.3 기능 추가 억제

다음 질문을 모두 통과하지 못하면 새 UI 요소를 추가하지 않는다.

1. 핵심 시연 흐름에 필요한가?
2. 기존 요소로 표현할 수 없는가?
3. 모바일에서도 유지할 가치가 있는가?
4. 출처·상태·실패 규칙이 정의됐는가?
5. E2E 또는 수동 인수 방법이 있는가?

## 4. 공통 디자인 시스템

### 4.1 디자인 토큰

전역 CSS 변수로 아래 역할을 제공한다. 실제 HEX 값은 현재 테마와 대비 검증 후 확정하되 역할 이름을 화면별로 재정의하지 않는다.

| 역할 | 용도 |
|---|---|
| `--bg-app` | 앱 최하단 배경 |
| `--bg-surface` | 기본 카드·sidebar |
| `--bg-elevated` | popover·drawer·tooltip |
| `--border-subtle` | 일반 구분선 |
| `--border-focus` | keyboard focus |
| `--text-primary` | 제목·핵심 수치 |
| `--text-secondary` | 설명·메타데이터 |
| `--text-tertiary` | 보조·비활성 정보 |
| `--accent-primary` | 핵심 CTA·선택 상태 |
| `--state-positive` | 정상·상승 |
| `--state-negative` | 오류·하락 |
| `--state-warning` | 지연·부분 데이터 |
| `--state-info` | 기준·참고 정보 |

간격은 4px 배수를 기본으로 하고 6px, 10px 등 기존 예외는 시각 검토 후 제한적으로 유지한다. 주요 카드 padding은 데스크톱 20~24px, 모바일 16~18px 범위로 통일한다.

### 4.2 타이포그래피

| 계층 | 목적 | 규칙 |
|---|---|---|
| Display | 페이지 핵심 수치 | 한 화면에서 제한적으로 사용 |
| H1 | route 제목 | 페이지당 하나 |
| H2 | 주요 섹션 | 카드 묶음 또는 핵심 패널 제목 |
| H3 | 카드 제목 | 수치보다 강하지 않게 표현 |
| Body | 설명 | 모바일 최소 14px 권장 |
| Meta | 출처·시각·상태 | 작아도 대비 기준 충족 |

- 숫자 열과 가격은 tabular number 사용을 권장한다.
- 긴 종목명·뉴스 제목은 임의 절단 전에 2줄 표시를 우선한다.
- 10px 미만 텍스트는 법적 면책 등 불가피한 경우 외에는 사용하지 않는다.

### 4.3 아이콘

- 문자 기호 `⌂`, `⌕`, `☆`, `◫`, `♢`는 최종 UI에서 사용하지 않는다.
- 하나의 SVG 아이콘 세트를 사용하고 stroke 두께와 viewBox를 통일한다.
- 아이콘만 있는 버튼은 `aria-label`과 tooltip을 제공한다.
- 동일 기능은 route와 화면에 관계없이 동일 아이콘을 사용한다.
- 상태 전달을 아이콘만으로 하지 않고 텍스트 또는 접근 가능한 이름을 함께 제공한다.
- 앱 로고와 기능 아이콘은 구분하며 기능 아이콘에 브랜드 glow를 적용하지 않는다.

### 4.4 버튼과 입력

- 버튼 높이는 기본 40px, 모바일 핵심 조작은 최소 44px로 한다.
- Primary CTA는 한 화면의 한 작업 흐름에서 하나를 원칙으로 한다.
- Secondary, ghost, danger 버튼의 색상과 hover/focus/disabled/loading 상태를 공통화한다.
- disabled 버튼은 이유를 인접 문구 또는 tooltip으로 설명한다.
- 입력 오류는 색상뿐 아니라 문구와 `aria-describedby`로 연결한다.
- 비동기 제출 중에는 중복 요청을 막고 진행 중 label을 표시한다.

### 4.5 카드와 구분

- 카드 중첩은 최대 2단계로 제한한다.
- border, 배경색, shadow를 동시에 강하게 사용하지 않는다.
- 선택 상태와 hover 상태를 구분한다.
- 클릭 가능한 카드에는 focus-visible 상태가 있어야 한다.
- 데이터 표는 행 hover보다 정렬, 단위, 빈 값의 의미가 먼저 명확해야 한다.

## 5. App Shell과 내비게이션

### 5.1 Sidebar

- 펼침 240px, 접힘 72px 목표를 유지한다.
- 접힘 상태에서도 아이콘, tooltip, active route가 식별되어야 한다.
- 그룹 간 간격과 메뉴 행 높이를 통일한다.
- ADMIN 메뉴는 USER에게 DOM 자체가 렌더링되지 않는다.
- 사용자 정보와 로그아웃은 주 메뉴보다 시각 우선순위를 낮춘다.

### 5.2 Topbar

- 현재 route 제목, 전역 종목 검색, 환율, API·실시간 상태의 우선순위를 고정한다.
- 좁은 화면에서는 상태 정보를 무작정 숨기지 않고 요약 badge 또는 drawer로 이동한다.
- 검색 popover는 loading, empty, metadata-only, unavailable 상태를 구분한다.
- 검색 결과에서 시장, 심볼, 한글명·영문명, 데이터 준비 상태를 일관되게 표시한다.

### 5.3 모바일

- 390px에서 bottom navigation이 본문을 가리지 않는다.
- More drawer는 focus trap, Escape, backdrop close, trigger focus 복귀를 지원한다.
- route 전환 후 H1 또는 주 제목으로 focus를 이동한다.
- 좌우 스크롤이 필요한 데이터는 의도된 영역 안에서만 발생한다.

## 6. 데이터 신뢰도 UI

### 6.1 공통 상태 모델

모든 시세·차트·환율·뉴스·공시·AI 결과는 가능한 경우 아래 메타데이터를 제공한다.

| 필드 | 화면 표현 |
|---|---|
| `source` | KIS, Finnhub, Open DART, SEC EDGAR, NAVER API HUB, DEMO |
| `asOf`/`publishedAt` | 사용자가 이해하는 현지 또는 명시된 시간대 |
| `freshness` | LIVE, DELAYED, REFERENCE, STALE, DEMO |
| `marketState` | 장전, 장중, 장후, 마감, 휴장 |
| `lastUpdatedAt` | 마지막 성공 갱신 시각 |

### 6.2 상태 배지

- `LIVE`: 정상 연결된 실시간 또는 명세상 실시간 데이터
- `DELAYED`: 공급자 지연 데이터이며 지연 시간을 가능한 경우 함께 표시
- `REFERENCE`: Frankfurter 등 기준환율과 같이 실시간이 아닌 참고값
- `STALE`: 마지막 정상값이며 최신 수집 실패 상태
- `DEMO`: 실제 시장 데이터로 오해할 수 없는 시연용 값
- `PARTIAL`: 일부 리소스만 준비된 상태
- `METADATA_ONLY`: 제목·발행처·링크만 활용 가능한 콘텐츠

색상만으로 상태를 구분하지 않는다. 배지는 축약어보다 사용자가 이해할 수 있는 한글 label을 우선한다.

### 6.3 갱신 실패

- 이미 표시 중인 정상 데이터가 있으면 화면을 비우지 않는다.
- 기존 데이터를 유지하고 마지막 성공 시각, 실패 상태, 다시 시도 버튼을 표시한다.
- LIVE 실패 시 DEMO로 조용히 전환하지 않는다.
- 오류 메시지는 공급자 내부 예외 대신 사용자 행동과 현재 보존 상태를 설명한다.

## 7. 화면별 폴리싱 계약

### 7.1 로그인

- 다크 배경에서 로고, 문구, 입력 label이 대비 기준을 충족한다.
- 데모 계정은 편의를 제공하되 실제 로그인보다 더 강한 CTA처럼 보이지 않는다.
- API 연결 상태와 로그인 가능 여부를 구분한다.
- 오류 후 입력값과 focus를 안전하게 유지한다.
- 390px 세로 화면에서 핵심 로그인 버튼과 데모 계정이 스크롤로 접근 가능하다.

### 7.2 대시보드

- 모든 기능의 복제 화면이 아니라 요약과 다음 행동을 제공한다.
- 관심종목, 최근 콘텐츠, 포트폴리오, AI 변화 요약의 정보 밀도를 맞춘다.
- 카드마다 `전체 보기` 또는 명확한 상세 route를 제공한다.
- 대시보드 수치는 기준 통화와 기준 시각을 표시한다.

### 7.3 종목 탐색·상세

- 현재 종목명, 시장, 심볼, 통화와 데이터 상태가 상단에서 항상 확인된다.
- overview, technical, content, briefing 탭은 동일 canonical 종목을 유지한다.
- metadata-only 종목을 다른 종목의 가격으로 대체하지 않는다.
- 직접 URL, 새로고침, 뒤로가기에도 선택 종목과 탭을 복원한다.

### 7.4 뉴스·공시

- 뉴스와 공시, 공식 출처, AI 허용 상태를 badge로 명확히 구분한다.
- 제목, 종목, 발행처, 시각, 출처, 분석 상태의 시각 순서를 고정한다.
- 긴 제목은 모바일에서 최소 2줄을 허용한다.
- 필터 변경은 page 0으로 이동하고 URL query와 일치해야 한다.
- 원문 링크는 새 창, `noopener noreferrer`, 안전한 protocol 검증을 유지한다.
- 콘텐츠가 없을 때 기간·필터를 조정할 수 있는 행동을 안내한다.

### 7.5 포트폴리오·알림

- 통화와 환율 기준을 수익·평가 금액 바로 옆에 표시한다.
- 증가·감소는 부호, 색상, label을 함께 사용한다.
- 삭제·해제는 실수 방지와 결과 feedback을 제공한다.
- 저장 중 중복 제출을 막고 성공·실패를 screen reader에도 알린다.

### 7.6 관리자

- 호출 수, token, 추정 비용, cache HIT/MISS, 실패를 같은 기간 기준으로 비교한다.
- 비용은 공급자 실제 청구액이 아닌 설정 단가 기반 추정치임을 명시한다.
- 비율 그래프에 분모와 기간을 제공한다.
- 빈 운영 데이터와 수집 실패를 0으로 오인하게 만들지 않는다.

## 8. 상세 차트와 기술적 분석

### 8.1 차트 기본 정보

- 종목, interval, 기간, 통화, 시간대, 데이터 상태를 차트 주변에서 확인한다.
- 가격 축과 거래량 단위를 현지화하고 과도한 소수점을 제거한다.
- 장중 미완성 봉은 완성 봉과 구분한다.
- 데이터가 부족하면 필요한 개수와 현재 개수를 설명한다.

### 8.2 툴바

- interval, 기간, 지표, 그리기, 전체화면을 시각적으로 그룹화한다.
- 선택 상태는 색상, 배경, `aria-pressed`를 함께 사용한다.
- 지표 초기화와 그리기 전체 삭제를 분리한다.
- destructive 조작은 실행 범위를 명확히 표현한다.
- 모바일에서는 툴바를 여러 줄로 억지 배치하지 않고 drawer 또는 bottom sheet로 분리할 수 있다.

### 8.3 지표 범례

- 활성 지표 이름, 색상, 현재 값, 파라미터를 표시한다.
- 차트 선과 범례 색상이 정확히 일치해야 한다.
- RSI, MACD 등 별도 pane 지표는 가격 지표와 그룹을 구분한다.
- 값이 계산 불가능하면 0 대신 `데이터 부족`을 표시한다.

### 8.4 상호작용

- 확대·이동·십자선·tooltip이 마우스와 touch에서 동작한다.
- 추세선·수평선은 선택, 이동, 삭제와 시각적 활성 상태가 있어야 한다.
- 전체화면 진입·종료 후 차트 크기를 다시 계산한다.
- route 이탈 시 listener와 chart instance를 정리한다.
- tooltip이 화면 밖으로 잘리거나 중요한 toolbar를 가리지 않는다.

## 9. AI 분석 경험

### 9.1 결과 구조

AI 결과는 아래 순서를 기본으로 한다.

```text
한 줄 결론
→ 긍정 근거
→ 위험·반대 근거
→ 기술·뉴스·공시 관점 상태
→ 검증 가능한 evidence
→ 데이터 한계와 면책
→ 생성·캐시 메타데이터
```

### 9.2 근거와 추적

- AI 문장에 사용된 evidence ID를 화면의 실제 데이터로 이동하거나 펼칠 수 있어야 한다.
- 존재하지 않는 근거 ID는 렌더링하지 않는다.
- 출처 링크, 기준 시각, 입력 데이터 범위와 계산 버전을 가능한 범위에서 제공한다.
- 기술, 뉴스, 공시, 정량 데이터의 관점 충돌을 단순 평균으로 숨기지 않는다.
- 데이터가 부족하면 중립 결론을 강제하지 말고 `분석 근거 부족` 상태를 표시한다.

### 9.3 AI 운영 메타데이터

- 생성 시각
- 모델·프롬프트 버전
- cache HIT/MISS 또는 저장 결과 복구
- token과 추정 비용
- 실패·부분 성공 상태

일반 사용자에게는 핵심 메타데이터만 제공하고 관리자 화면에서 상세 운영 로그를 제공한다.

### 9.4 금지 표현

- 매수·매도 명령
- 목표주가와 확정 수익률
- 데이터가 없는 원인에 대한 추측
- 기사 원문을 읽지 않았는데 읽은 것처럼 표현
- DEMO 또는 STALE 결과를 최신 실데이터로 표현

## 10. 비동기 상태 디자인

각 route와 주요 카드에는 다음 상태를 독립적으로 설계한다.

| 상태 | 필수 표현 |
|---|---|
| Initial loading | 레이아웃을 닮은 skeleton, 접근 가능한 진행 label |
| Background refresh | 기존 데이터 유지, 작은 갱신 상태 |
| Empty | 빈 이유, 조건, 다음 행동 |
| Partial | 준비된 데이터와 누락된 데이터 분리 |
| Error | 보존된 데이터 여부, 다시 시도 |
| Offline | 오프라인에서 가능한 범위와 재연결 안내 |
| Unauthorized | 로그인 또는 권한 route 안내 |
| Not Found | 안전한 기본 route 이동 |

- spinner만 중앙에 표시하고 문맥을 모두 지우지 않는다.
- skeleton은 실제 레이아웃 이동을 줄이는 크기로 제공한다.
- 요청 순서가 역전되어 이전 응답이 최신 화면을 덮지 않도록 abort 또는 request identity를 사용한다.

## 11. 접근성

- 일반 텍스트 WCAG AA 4.5:1, 큰 텍스트·그래픽 핵심 요소 3:1 대비를 목표로 한다.
- 모든 기능은 keyboard만으로 접근 가능해야 한다.
- focus-visible이 배경과 명확히 구분되어야 한다.
- route 전환, pagination, 저장 결과, 오류는 적절한 live region을 사용한다.
- chart 자체가 읽히지 않는 환경을 위해 핵심 가격·변화·지표 값을 텍스트로 제공한다.
- 색상만으로 상승, 하락, 성공, 오류를 전달하지 않는다.
- dialog와 drawer는 이름, focus trap, Escape, focus 복귀를 제공한다.
- `prefers-reduced-motion`에서 불필요한 pulse와 transition을 줄인다.

## 12. 반응형·PWA

검수 viewport:

- 1440×900 데스크톱
- 1024×768 작은 노트북·태블릿 가로
- 768×1024 태블릿 세로
- 390×844 모바일

필수 규칙:

- body 가로 overflow가 없어야 한다.
- bottom navigation과 safe area가 마지막 콘텐츠를 가리지 않는다.
- standalone PWA에서도 route, 뒤로가기, 새로고침이 동작한다.
- offline shell의 로고·문구·재시도 버튼이 현재 브랜드와 일치한다.
- favicon, 192/512 아이콘, maskable, apple-touch icon을 실제 설치 화면에서 확인한다.
- 아이콘 변경 인수 시 기존 설치 제거와 OS 아이콘 캐시 영향도 기록한다.

## 13. 체감 성능

- route 변경 시 공통 App Shell을 다시 마운트하지 않는다.
- 대형 차트와 목록은 불필요한 재계산·재렌더링을 줄인다.
- 이미지에는 실제 표시 크기에 맞는 자산을 사용한다.
- 첫 화면에서 사용하지 않는 대형 route는 lazy loading을 검토한다.
- skeleton 표시 중 layout shift를 최소화한다.
- 콘텐츠 page size 최대값은 명세상 50을 유지한다.
- 100,000개 콘텐츠 fixture 성능은 `17_NAVIGATION_AND_CONTENT_LIST_SPEC.md`의 p95 인수와 연결한다.

성능 최적화가 데이터 정확성, 접근성 또는 실패 상태를 제거하는 이유가 되어서는 안 된다.

## 14. 구현 우선순위

### P0 — 대회·포트폴리오 필수

1. 문자 아이콘을 단일 SVG 아이콘 세트로 교체한다.
2. 버튼, 입력, 카드, 글자, 간격 토큰을 통일한다.
3. LIVE/DELAYED/REFERENCE/STALE/DEMO/PARTIAL 상태 배지를 통일한다.
4. loading, empty, partial, error, offline 화면을 route별로 검수한다.
5. 다크 배경에서 로고와 핵심 텍스트 대비를 수정한다.
6. 390px 모바일과 PWA standalone 핵심 흐름을 회귀한다.
7. 직접 URL·새로고침·뒤로가기 상태 복원을 완료한다.

### P1 — 전문 투자 서비스 인상

1. 차트 툴바를 그룹화하고 모바일 조작을 정리한다.
2. 활성 지표 범례, 색상, 현재 값과 파라미터를 제공한다.
3. AI 결론·찬반 근거·evidence·한계의 시각 계층을 통일한다.
4. 뉴스·공시 카드와 필터의 정보 밀도를 정리한다.
5. 사용자 feedback과 관리자 지표의 기간·단위를 명확히 한다.

### P2 — 제출 증적

1. desktop·mobile·PWA 최종 캡처를 고정한다.
2. cache MISS/HIT 전후 화면과 관리자 비용 집계를 촬영한다.
3. 외부 API·Gemini 실패 상태를 촬영한다.
4. 5분 영상, 발표 Q&A, A1 패널에 동일한 용어와 수치를 사용한다.

P0가 끝나기 전에 새로운 대형 기능을 추가하지 않는다.

### 15.1 자동화

- lint

- route 직접 진입·새로고침·뒤로가기

### 15.2 시각 회귀 체크리스트

- 로고가 배경에 묻히거나 흰 사각형으로 보이지 않는다.
- sidebar 펼침·접힘에서 메뉴 정렬이 흔들리지 않는다.
- H1, 핵심 가격, CTA가 동시에 경쟁하지 않는다.
- badge가 줄바꿈되어 데이터 행을 과도하게 키우지 않는다.
- 긴 한국어·영문 종목명과 뉴스 제목이 레이아웃을 깨지 않는다.
- 차트 tooltip과 popover가 viewport 밖으로 잘리지 않는다.
- skeleton에서 실제 데이터로 바뀔 때 큰 layout shift가 없다.
- 밝기와 색을 낮춘 모니터에서도 핵심 상태를 읽을 수 있다.

### 15.3 수동 시연 시나리오

```text
로그인
→ 종목 검색
→ 상세 차트와 기술지표
→ 뉴스·공시 및 공식 원문
→ AI 기술 해설과 근거
→ 일일 변화 브리핑과 관점 충돌
→ 같은 요청 재실행으로 cache HIT
→ 관리자 비용·실패 지표
→ 모바일/PWA 전환
```

각 단계는 1~2번의 명확한 조작으로 다음 화면에 도달해야 한다.

완료 판정에는 다음 자료를 함께 남긴다.

- 390px mobile 캡처

- 5분 시연 영상의 최종 동선과 시간표

초기 목업, 생성 이미지, DEMO 수치를 실제 구현 증적으로 대체하지 않는다.

## 17. 인수 조건

- [ ] 공통 색상·간격·글자·button·input·card 토큰이 화면별 임의값보다 우선한다.
- [ ] 문자형 주 메뉴 아이콘이 하나의 SVG 아이콘 세트로 교체된다.
- [ ] desktop Sidebar, Topbar, mobile Bottom Navigation의 active·hover·focus 상태가 일관된다.
- [ ] 390px에서 body 가로 overflow와 bottom navigation 콘텐츠 가림이 없다.
- [ ] 로그인과 App Shell의 로고가 다크 배경에서 식별되고 불필요한 이미지 배경이 없다.
- [ ] 주요 금융 데이터에 source, 기준 시각과 LIVE/DELAYED/REFERENCE/STALE/DEMO 상태가 표시된다.
- [ ] LIVE 장애가 DEMO로 조용히 대체되지 않는다.
- [ ] 기존 데이터가 있는 갱신 실패에서 화면이 비워지지 않는다.
- [ ] 모든 주요 route에 loading, empty, partial, error, offline 상태가 있다.
- [ ] 차트 toolbar가 기능군별로 구분되고 선택 상태를 키보드와 screen reader가 인식한다.
- [ ] 활성 기술지표의 이름, 색상, 현재 값과 파라미터를 확인할 수 있다.
- [ ] AI 결과에 결론, 긍정·위험 근거, evidence, 기준 시각, 한계와 cache 상태가 구분된다.
- [ ] 뉴스·공시의 권리·출처·AI 분석 가능 상태가 오인 없이 구분된다.
- [ ] 직접 URL, 새로고침, 뒤로가기, standalone PWA에서 route와 허용된 query 상태가 복원된다.
- [ ] keyboard, focus-visible, dialog focus trap, live region과 기본 대비가 검수된다.
- [ ] desktop·390px·PWA 시연 흐름이 동일 데이터와 용어를 사용한다.
- [ ] production build, lint, backend tests, Playwright와 `git diff --check`가 통과한다.
- [ ] 실제 구현 화면으로 5분 영상과 발표 자료를 제작한다.
