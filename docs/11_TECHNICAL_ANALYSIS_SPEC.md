# FinWatch 기술적 분석 상세 명세

상태: Living Spec v1.1  
적용 범위: `GET /api/v1/stocks/{symbol}/technical`, 종목 상세 기술지표 화면  
현재 기준 구현: `TechnicalAnalysisCalculator`, `StockQueryService`

## 1. 목적과 범위

이 문서는 가격 이력으로부터 이동평균선, RSI, MACD와 종합 신호를 계산하는 규칙을 재현 가능한 수준으로 고정한다. 같은 입력과 계산 버전을 사용하면 실행 환경과 관계없이 같은 결과를 반환해야 한다.

기술적 분석 결과는 과거 가격을 수학적으로 변환한 참고 정보이며 다음 기능은 제공하지 않는다.

- 미래 가격이나 수익률 예측
- 자동 매매 또는 주문 실행
- 개인별 매수·매도 추천
- 거래 비용을 포함한 백테스트
- 재무제표·거시경제·뉴스를 결합한 투자 등급

## 2. 명세 상태 용어

| 용어 | 의미 |
|---|---|
| 현재 | 코드와 API에 이미 적용된 동작 |
| 목표 | MVP 공개 전 구현하고 인수 테스트할 동작 |
| 확장 목표 | 핵심 MVP 이후 대회·포트폴리오 완성본에 포함할 동작 |
| TBD | 데이터 공급자 확정 등 선행 결정이 필요한 항목 |

수식, 임계값, 초기값 또는 반올림 규칙을 변경하면 기존 결과가 달라지므로 단순 리팩터링으로 취급하지 않는다. 변경 시 이 문서, API 명세, 테스트 벡터와 계산 버전을 함께 갱신한다.

## 3. 입력 데이터 계약

### 3.1 현재 입력

- 데이터 원본은 `market_prices`의 `price_interval = "1D"` 행이다.
- 하나의 종목에 대한 종가(`close_price`)를 `recorded_at` 오름차순으로 전달한다.
- 계산에는 최소 60개의 종가가 필요하다.
- 최신 종가는 입력 배열의 마지막 값이다.
- 현재 계산은 거래량, 시가, 고가, 저가를 사용하지 않는다.
- 조회 시점에 계산하며 분석 결과를 별도 테이블에 저장하지 않는다.

### 3.2 목표 데이터 품질 규칙

계산 전에 다음 조건을 검증해야 한다.

1. 종목은 활성 상태이고 시장과 통화가 식별되어야 한다.
2. 일봉은 `(stock_id, price_interval, recorded_at)` 기준으로 중복되지 않아야 한다.
3. `recorded_at`은 엄격한 오름차순이어야 한다.
4. OHLC 가격은 0보다 커야 하고 거래량은 0 이상이어야 한다.
5. 각 봉은 `low <= min(open, close)` 및 `max(open, close) <= high`를 만족해야 한다.
6. `close_price`는 `null`, `NaN`, 무한대일 수 없다.
7. 주말과 휴장일로 인한 날짜 간격은 결측으로 보지 않는다.
8. 실제 거래일의 누락 여부는 거래소 캘린더로 판별한다.
9. 누락된 종가를 직전 값이나 0으로 임의 보간하지 않는다.
10. 장중 미완성 일봉은 일봉 기술적 분석에서 제외한다.

품질 검증에 실패하면 잘못된 신호를 생성하지 않고 명확한 데이터 오류로 처리한다. 외부 데이터 정규화와 거래소 캘린더 규칙은 `06_DATA_PROVIDER_SPEC.md`를 따른다.

### 3.3 수정주가 결정 게이트

배당, 액면분할, 병합 같은 기업행동을 반영하지 않은 종가는 지표를 왜곡할 수 있다. LIVE 공급자 연결 전 다음을 확정한다.

- 공급자가 제공하는 값이 원주가인지 수정주가인지
- 수정 기준과 과거 데이터 재작성 정책
- 수정주가와 원주가 중 차트·지표에 사용할 값
- 기업행동 반영 후 기존 캐시와 화면 데이터 무효화 방법

확정 전에는 `DEMO` 데이터만 사용하며 LIVE 기술 신호라고 표시하지 않는다.

## 4. 공통 계산 규칙

- 계산 정밀도는 소수점 이하 4자리다.
- 외부로 반환하는 값은 `RoundingMode.HALF_UP`으로 반올림한다.
- 중간 계산은 필요한 경우 10~12자리 정밀도를 사용하고 마지막에 4자리로 맞춘다.
- 가격 목록은 과거에서 최신 순서로 해석한다.
- 현재 기간은 MA 5/20/60, RSI 14, MACD 12/26/9로 고정한다.
- 비교는 반올림된 표시 문자열이 아니라 계산용 숫자로 수행한다.

알고리즘 파라미터를 설정으로 바꾸더라도 캐시나 API 결과에 사용한 파라미터와 계산 버전을 식별할 수 있어야 한다.

## 5. 단순 이동평균선(SMA)

### 5.1 계산식

기간 `N`의 단순 이동평균은 최신 `N`개 종가의 산술평균이다.

```text
SMA(N) = (C[t-N+1] + ... + C[t]) / N
```

현재 다음 값을 계산한다.

- `ma5`: 최신 5개 종가 평균
- `ma20`: 최신 20개 종가 평균
- `ma60`: 최신 60개 종가 평균

### 5.2 이동평균 신호

| 조건 | 신호 |
|---|---|
| 최신 종가 `> MA20` 이고 `MA5 > MA20` | `BUY` |
| 최신 종가 `< MA20` 이고 `MA5 < MA20` | `SELL` |
| 나머지 모든 경우 | `NEUTRAL` |

동일값은 돌파로 간주하지 않는다. 현재 `MA60`은 장기 추세 참고값으로 표시하지만 이동평균 신호 판정에는 사용하지 않는다. 골든크로스·데드크로스처럼 이전 봉과 현재 봉의 교차 사건은 핵심 MVP 범위가 아니며, 17절의 포트폴리오 완성 목표에서 별도 이벤트로 추가한다.

## 6. RSI

### 6.1 현재 계산 방식

현재 계산 버전 `technical-v2-wilder`는 첫 14개 변화량의 산술평균을 초기값으로 사용한 뒤 이후 변화량을 Wilder 방식으로 평활한다.

```text
delta[i] = C[i] - C[i-1]
gain     = max(delta, 0)의 14개 합
loss     = abs(min(delta, 0))의 14개 합
avgGain  = gain / 14
avgLoss  = loss / 14
RS       = avgGain / avgLoss
RSI      = 100 - 100 / (1 + RS)
```

예외 규칙:

| 조건 | RSI |
|---|---:|
| 상승분과 하락분이 모두 0 | 50.0000 |
| 하락분만 0 | 100.0000 |
| 상승분만 0 | 0.0000 |

### 6.2 RSI 신호

| 조건 | 신호 | 의미 |
|---|---|---|
| `RSI >= 70` | `SELL` | 과매수 참고 구간 |
| `RSI <= 30` | `BUY` | 과매도 참고 구간 |
| `30 < RSI < 70` | `NEUTRAL` | 중립 구간 |

경계값 30과 70은 각각 `BUY`, `SELL`에 포함한다. RSI 신호는 추세 반전을 보장하지 않는다.

### 6.3 알고리즘 변경 규칙

Wilder RSI로 전환하면 같은 데이터의 결과가 달라진다. 전환 시 다음을 모두 수행한다.

1. 새 계산 버전을 발급한다.
2. 기준 데이터셋과 기대값을 새로 고정한다.
3. 기존 버전과 새 버전의 차이를 문서화한다.
4. API와 화면에 계산 버전을 표시한다.
5. 임계값 변경 여부를 별도로 검토한다.

## 7. MACD

### 7.1 EMA 정의

기간 `N`의 지수이동평균 승수는 다음과 같다.

```text
alpha = 2 / (N + 1)
EMA[0] = C[0]
EMA[t] = EMA[t-1] + alpha * (C[t] - EMA[t-1])
```

현재 구현은 최초 `N`개 SMA가 아니라 **전체 입력의 첫 종가를 EMA 초기값으로 사용**한다. 다른 차트 도구와 비교할 때 반드시 같은 초기화 규칙을 사용한다.

### 7.2 MACD 계산식

```text
fastEMA[t]   = EMA(12)
slowEMA[t]   = EMA(26)
MACD[t]      = fastEMA[t] - slowEMA[t]
signal[t]    = MACD 시계열의 EMA(9)
histogram[t] = MACD[t] - signal[t]
```

API는 최신 시점의 `value`, `signalLine`, `histogram`을 반환한다.

### 7.3 MACD 신호

| 조건 | 신호 |
|---|---|
| `histogram > 0` | `BUY` |
| `histogram < 0` | `SELL` |
| `histogram = 0` | `NEUTRAL` |

현재 신호는 히스토그램 부호만 사용한다. 0선 돌파나 직전 봉 대비 MACD/Signal 교차 사건은 판정하지 않는다.

## 8. 종합 신호

각 지표 신호를 다음 점수로 변환한다.

| 신호 | 점수 |
|---|---:|
| `BUY` | +1 |
| `NEUTRAL` | 0 |
| `SELL` | -1 |

```text
score = movingAverageScore + rsiScore + macdScore
```

| 합계 조건 | `summarySignal` |
|---|---|
| `score > 0` | `BUY` |
| `score = 0` | `NEUTRAL` |
| `score < 0` | `SELL` |

세 지표의 가중치는 모두 같다. 따라서 강한 상승 추세에서도 RSI가 과매수이면 `MA=BUY`, `RSI=SELL`, `MACD=BUY`가 되어 종합은 `BUY`가 될 수 있다. 종합 신호는 다수결 성격의 요약일 뿐 신뢰도나 확률이 아니다.

## 9. API 계약

### 9.1 현재 응답

`GET /api/v1/stocks/{symbol}/technical`은 다음 정보를 반환한다.

```json
{
  "symbol": "000660",
  "calculatedAt": "2026-07-13T02:30:00Z",
  "summarySignal": "BUY",
  "movingAverages": {
    "ma5": 2701000.0000,
    "ma20": 2689000.0000,
    "ma60": 2612000.0000,
    "signal": "BUY"
  },
  "rsi": {
    "period": 14,
    "value": 68.4000,
    "signal": "NEUTRAL"
  },
  "macd": {
    "value": 18320.5000,
    "signalLine": 14210.1000,
    "histogram": 4110.4000,
    "signal": "BUY"
  },
  "disclaimer": "기술적 신호는 투자 권유가 아닌 참고 정보입니다."
}
```

`calculatedAt`은 서버 계산 시각이 아니라 계산에 사용한 마지막 일봉의 `recorded_at`이다.

### 9.2 목표 메타데이터

LIVE 데이터 연결 전 다음 필드를 추가하는 API 변경을 검토한다.

- `calculationVersion`: 수식·초기값·임계값 묶음 버전
- `interval`: 계산 입력 봉 간격, MVP는 `1D`
- `sampleCount`: 사용한 입력 개수
- `source`: 가격 데이터 공급자
- `adjusted`: 수정주가 적용 여부
- `freshness`: `FRESH`, `STALE`, `DEMO`

필드 추가 시 `03_API_SPEC.md`, 프런트 타입, 통합 테스트를 같은 커밋에서 갱신한다.

## 10. 오류 처리

| 상황 | HTTP/코드 | 현재 또는 목표 동작 |
|---|---|---|
| 인증 없음·만료 | `401` | 공통 보안 응답 |
| 비활성 또는 존재하지 않는 종목 | `404 STOCK_NOT_FOUND` 목표 | 현재는 404 메시지 반환 |
| 가격 이력 없음 | `404 PRICE_HISTORY_NOT_FOUND` 목표 | 신호를 생성하지 않음 |
| 일봉 60개 미만 | `422 TECHNICAL_DATA_INSUFFICIENT` 목표 | 현재 422 메시지 반환 |
| 잘못된 OHLC·중복·순서 오류 | `422 MARKET_DATA_INVALID` 목표 | 데이터 품질 오류 기록 |
| 지원하지 않는 간격·파라미터 | `400 VALIDATION_ERROR` | 계산하지 않음 |

데이터 부족을 `NEUTRAL`로 반환해서는 안 된다. `NEUTRAL`은 충분하고 유효한 데이터로 계산한 결과일 때만 사용한다.

## 11. 화면 표시 규칙

- 가격과 지표의 기준 시각, 데이터 출처, `DEMO` 여부를 함께 표시한다.
- `BUY`, `SELL`, `NEUTRAL`을 색상만으로 구분하지 않고 텍스트 또는 아이콘을 병기한다.
- RSI에는 현재 값과 30·70 기준선을 표시한다.
- MACD에는 MACD선, Signal선, Histogram의 의미를 구분한다.
- MA5·MA20·MA60과 가격 차트는 같은 시간축을 사용한다.
- 데이터가 부족하면 빈 차트를 가짜 값으로 채우지 않고 원인을 표시한다.
- 오래된 데이터는 신호보다 데이터 지연 경고를 우선 표시한다.
- 모든 화면에 투자 권유가 아니라는 고지 문구를 유지한다.

### 11.1 상세 차트 목표

현재 `StockDetail.tsx`는 최근 3개월 종가를 단순 SVG 면적·선 차트로 표시한다. 다음 구현 단계에서는 이를 **Lightweight Charts 기반 상세 차트**로 교체한다. 라이브러리 버전은 구현 시점에 검증한 버전을 `package.json`과 lockfile에 고정한다.

MVP 상세 차트의 필수 기능은 다음과 같다.

1. OHLC 캔들 차트
2. 마우스·트랙패드·터치 확대/축소와 좌우 이동
3. 십자선과 해당 시점 데이터 툴팁
4. 기간 선택
5. 전체화면
6. 사용자 추세선과 수평선

### 11.2 캔들 차트

- `PricePoint`의 `time`, `open`, `high`, `low`, `close`를 사용한다.
- 시간은 중복되지 않는 오름차순으로 변환한 뒤 시리즈에 전달한다.
- 상승·하락·보합 색상을 구분하고 범례에도 방향을 텍스트로 제공한다.
- 가격 축은 종목 통화와 시장의 호가 정밀도에 맞게 표시한다.
- 시간 축은 거래소 현지 거래일을 표시하되 서버 원본 시각은 UTC를 유지한다.
- 데이터가 없는 날짜에 가짜 캔들을 만들지 않는다.
- 불완전하거나 유효하지 않은 OHLC 봉은 그리지 않고 데이터 오류 상태를 표시한다.
- 종목 또는 기간 변경 시 기존 시리즈 데이터를 새 응답으로 완전히 교체한다.

### 11.3 확대·이동

- 마우스 휠과 트랙패드로 시간 축을 확대·축소할 수 있어야 한다.
- 차트 드래그로 과거와 최신 구간을 좌우 이동할 수 있어야 한다.
- 모바일에서는 핀치 확대와 한 손가락 좌우 이동을 지원한다.
- `초기화` 동작으로 선택 기간 전체가 보이는 범위로 돌아갈 수 있어야 한다.
- 새 데이터가 들어와도 사용자가 과거 구간을 보고 있다면 강제로 최신 위치로 이동시키지 않는다.
- 확대·이동은 브라우저 전체 페이지의 예기치 않은 스크롤과 충돌하지 않아야 한다.

### 11.4 십자선과 툴팁

- 포인터가 차트 안에 있을 때 시간·가격 십자선을 표시한다.
- 툴팁은 해당 캔들의 날짜, 시가, 고가, 저가, 종가와 거래량을 표시한다.
- MA 오버레이를 함께 표시할 경우 같은 시점의 MA5·MA20·MA60 값도 표시한다.
- 값이 없는 시점에서는 직전 값을 현재 값처럼 표시하지 않는다.
- 모바일에서는 길게 누르거나 드래그하여 십자선을 탐색할 수 있어야 한다.
- 키보드 사용자를 위한 최신 봉 요약과 접근 가능한 데이터 표 또는 동등한 텍스트 대안을 제공한다.

### 11.5 기간 선택

| 선택값 | API `period` | 간격 | 상태 |
|---|---|---|---|
| 1개월 | `1M` | `1D` | 필수 |
| 3개월 | `3M` | `1D` | 필수, 기본값 |
| 6개월 | `6M` | `1D` | 필수 |
| 1년 | `1Y` | `1D` | 필수 |
| 전체 | `ALL` | `1D` | 필수 |

- 기간 버튼은 현재 선택값을 시각적 상태와 `aria-pressed`로 표시한다.
- 기간 변경 시 진행 중인 이전 요청을 취소하고 선택한 기간만 반영한다.
- 로딩 중에는 기존 데이터를 새 기간의 데이터인 것처럼 표시하지 않는다.
- 빈 데이터, API 오류와 DEMO 폴백 상태를 구분한다.
- 종목을 변경해도 기본 기간은 3개월로 초기화하지 않고 사용자의 현재 선택을 유지하는 것을 기본 정책으로 한다.
- 차트 봉 간격은 `1D`(일봉), `1W`(주봉), `1M`(월봉)을 지원한다. 주봉·월봉은 실제 일봉을 거래소 현지 시간 기준으로 집계하고 선택한 봉 간격에서 보조지표를 다시 계산한다.
- `/technical` 서버 종합 신호와 교차 이벤트의 기준 봉은 계속 일봉이다. 실시간 1분 봉은 WebSocket 체결의 인메모리 세션 버퍼를 사용하며, 차트 보조지표는 브라우저 표시용 계산으로 일봉 기술분석 API와 구분한다.

### 11.6 전체화면

- 차트 도구 모음의 버튼으로 전체화면 진입·종료를 제공한다.
- 지원 브라우저에서는 Fullscreen API를 사용하고, 지원하지 않으면 화면을 채우는 CSS 모달로 폴백한다.
- `Esc`로 종료할 수 있어야 하며 진입 전 포커스로 돌아간다.
- 전체화면 전환 후 컨테이너 크기를 다시 측정하여 차트가 잘리거나 흐려지지 않게 한다.
- 전체화면에서도 기간 선택, 십자선과 그리기 도구를 그대로 사용할 수 있어야 한다.
- 현재 전체화면 상태를 버튼 레이블과 `aria-pressed`로 노출한다.

### 11.7 추세선·수평선 그리기

Lightweight Charts 기본 시리즈와 별도로 플러그인·Primitive API 또는 프로젝트 내부 오버레이 계층을 사용해 구현한다. 특정 확장 라이브러리를 채택하기 전 라이선스와 현재 고정 버전 호환성을 확인한다.

#### 추세선

- 사용자가 `추세선` 도구를 선택하고 서로 다른 두 시점·가격을 지정해 선을 만든다.
- 두 앵커는 시간과 가격 데이터 좌표로 저장하며 화면 픽셀 좌표만 저장하지 않는다.
- 확대·이동·리사이즈 후에도 같은 데이터 지점을 유지한다.
- 선택한 선의 두 끝점을 드래그해 수정할 수 있어야 한다.

#### 수평선

- 사용자가 `수평선` 도구를 선택하고 가격 한 지점을 지정해 전체 가시 시간축에 선을 만든다.
- 가격 축에 해당 가격 레이블을 표시한다.
- 선택한 수평선을 드래그하여 가격을 변경할 수 있어야 한다.

#### 공통 편집 규칙

- 활성 도구와 선택된 선을 명확히 구분한다.
- `Delete`/`Backspace` 또는 화면 버튼으로 선택한 선을 삭제할 수 있어야 한다.
- `그리기 초기화`는 확인 후 현재 종목의 모든 사용자 선을 제거한다.
- 그리기 모드는 차트 이동 모드와 충돌하지 않도록 명시적으로 전환한다.
- 모바일에서는 도구 선택 후 탭·드래그로 앵커를 지정하고 최소 터치 영역을 보장한다.
- MVP의 선은 브라우저 메모리 상태로 유지하고 새로고침 시 사라져도 된다. 영구 저장을 추가할 경우 사용자·종목·간격별 스키마와 CRUD API를 먼저 명세한다.
- 사용자가 그린 선은 시스템 기술 신호와 다른 스타일로 표시하고 투자 판단 근거로 자동 해석하지 않는다.

### 11.8 차트 상태와 성능

- 차트는 ResizeObserver 등으로 컨테이너 크기 변경에 반응하고 컴포넌트 해제 시 이벤트와 인스턴스를 정리한다.
- 종목·기간 변경이 반복되어도 시리즈·이벤트 핸들러가 중복 생성되지 않아야 한다.
- 최신 요청보다 늦게 도착한 과거 요청 응답이 화면을 덮어쓰지 않아야 한다.
- 1년 및 전체 실제 일봉과 집계된 주봉·월봉을 일반 데스크톱·모바일에서 끊김 없이 탐색할 수 있어야 한다.
- 성능 수치는 실제 공급자 최대 데이터량을 확정한 뒤 `10_TEST_ACCEPTANCE_SPEC.md`의 브라우저 성능 기준으로 고정한다.

## 12. 캐시와 재계산

현재 기술적 분석은 요청할 때 DB 가격 이력을 읽어 매번 계산한다. 기술지표 캐시를 추가할 경우 키는 최소 다음 값을 포함한다.

```text
technical:{market}:{symbol}:1D:{latestRecordedAt}:{calculationVersion}
```

새 일봉 적재, 과거 가격 정정, 기업행동 반영 또는 계산 버전 변경 시 이전 캐시를 사용하지 않는다. TTL만으로 정확성을 보장하지 않는다.

## 13. 검증 전략

### 13.1 필수 결정론 테스트

| 입력 | 기대 결과 |
|---|---|
| 종가 100이 60개 | MA5/20/60 = 100.0000, RSI = 50.0000, MACD Histogram = 0.0000, 전체 `NEUTRAL` |
| 1씩 상승하는 종가 90개 | MA `BUY`, RSI = 100.0000 및 RSI `SELL`, MACD `BUY`, 전체 `BUY` |
| 1씩 하락하는 종가 90개 | MA `SELL`, RSI = 0.0000 및 RSI `BUY`, MACD `SELL`, 전체 `SELL` |
| 종가 59개 | 계산 거부, API `422` |
| RSI 정확히 30 | RSI `BUY` |
| RSI 정확히 70 | RSI `SELL` |
| 최신가와 MA20 또는 MA5와 MA20이 같음 | 해당 이동평균 조건은 `NEUTRAL` |

### 13.2 독립 교차검증

- 고정 CSV 데이터셋과 기대 결과를 테스트 자산으로 관리한다.
- SMA는 스프레드시트 산술평균과 비교한다.
- RSI 비교 도구는 단순 평균 방식을 사용하도록 설정한다.
- MACD 비교 도구는 첫 종가 EMA 초기화 방식을 사용해야 한다.
- 숫자 허용 오차는 외부 반환 정밀도 기준 `0.0001` 이하로 한다.
- 전체 입력, 사용 기간, 알고리즘 버전과 기대값 생성 근거를 테스트에 기록한다.

### 13.3 필수 API 테스트

- 정상 종목에서 필드, 기준 시각, 신호 열거값을 검증한다.
- 60개와 59개 경계를 각각 검증한다.
- 다른 사용자의 데이터와 관계없이 동일 시장 데이터에서 동일 결과가 나오는지 검증한다.
- 가격 이력의 최신 봉을 변경했을 때 `calculatedAt`과 결과가 함께 변경되는지 검증한다.
- 인증 401, 종목 없음 404, 데이터 부족 422를 검증한다.

## 14. 관측성과 운영

기술적 분석 요청 로그에는 비밀정보나 전체 가격 배열을 남기지 않고 다음을 구조화해서 기록한다.

- 요청 ID
- market, symbol, interval
- sampleCount, latestRecordedAt, source
- calculationVersion
- summarySignal
- 계산 시간
- 성공/실패와 표준 오류 코드

다음 조건은 운영 경고 후보로 집계한다.

- 활성 종목의 데이터가 신선도 기준을 초과함
- 60개 미만 데이터로 계산이 반복 실패함
- 잘못된 OHLC 또는 중복 봉 발견
- 같은 입력·버전에서 결과가 달라지는 결정론 위반

## 17. 포트폴리오 완성 목표 기술적 분석

이 절은 핵심 MVP를 불필요하게 지연시키지 않으면서 대회·포트폴리오 완성도를 높이기 위한 **확정 확장 목표**다. 지표를 많이 나열하는 것이 아니라 가격 추세, 거래량, 모멘텀과 변동성을 서로 다른 관점에서 설명하는 조합으로 제한한다.

### 17.1 최종 화면 구성

| 영역 | 필수 구성 |
|---|---|
| 메인 가격 패널 | OHLC 캔들, MA5·MA20·MA60, 볼린저 밴드, 골든·데드크로스와 MACD 교차 이벤트 마커 |
| 거래량 패널 | 상승·하락 거래량 히스토그램, Volume MA20 |
| 보조지표 패널 | Wilder RSI14, MACD 12/26/9, ATR14 |
| 차트 도구 | 일봉·주봉·월봉·실시간 1분봉, 1M·3M·6M·1Y·ALL, 확대·이동·십자선, 전체화면, 추세선·수평선 |
| 표시 설정 | MA·거래량·볼린저 밴드·이벤트 마커 표시/숨김, RSI·MACD·ATR 패널 선택, 전체 초기화 |

기본 화면은 캔들, 거래량, MA5·MA20·MA60과 RSI를 표시한다. 볼린저 밴드, MACD, ATR과 이벤트 마커는 사용자가 켜고 끌 수 있게 하여 작은 화면과 모바일에서 과도한 정보 중첩을 막는다. 표시 설정은 최소 현재 브라우저 세션 동안 종목을 바꿔도 유지한다.

### 17.2 거래량 히스토그램과 Volume MA20

- 선택한 일봉·주봉·월봉의 거래량을 캔들과 동일한 시간축에 막대로 표시한다.
- 종가가 시가보다 높으면 상승, 낮으면 하락, 같으면 보합 스타일을 적용하고 색상 외 텍스트 범례를 제공한다.
- `Volume MA20`은 선택한 봉 간격의 최신 20개 거래량 산술평균이다.
- 거래량이 없거나 음수인 봉은 3.2의 데이터 품질 오류로 처리하며 0은 유효한 값으로 허용한다.
- 십자선 툴팁에는 해당 거래량, Volume MA20과 동일한 20일 평균 대비 배수를 표시한다. 평균이 0이면 배수는 `null`로 반환한다.
- 거래량은 가격 축과 분리된 패널·축을 사용하며 가격 종합 신호의 점수에는 포함하지 않는다.

### 17.3 볼린저 밴드 20·2

동일한 최신 20개 종가에 대해 모집단 표준편차를 사용한다.

```text
middle[t] = SMA20[t]
sigma[t]  = sqrt(sum((close[i] - middle[t])^2) / 20)
upper[t]  = middle[t] + 2 * sigma[t]
lower[t]  = middle[t] - 2 * sigma[t]
bandwidthPercent[t] = (upper[t] - lower[t]) / middle[t] * 100
```

- 20개 미만 구간에는 밴드 값을 만들지 않는다.
- 중심선, 상단선과 하단선은 같은 가격 패널에 표시하되 캔들을 가리지 않는 스타일을 사용한다.
- 십자선에서 같은 시점의 네 값을 확인할 수 있어야 한다.
- 상단·하단 접촉이나 돌파만으로 `BUY` 또는 `SELL`을 생성하지 않는다. 밴드는 변동성·가격 위치 참고값이며 종합 신호 점수에는 포함하지 않는다.

### 17.4 Wilder RSI14 전환

포트폴리오 완성본은 현재 단순 평균 RSI를 Wilder 평활 RSI로 교체한다.

```text
initialAvgGain = 첫 14개 gain의 합 / 14
initialAvgLoss = 첫 14개 loss의 합 / 14
avgGain[t] = (avgGain[t-1] * 13 + gain[t]) / 14
avgLoss[t] = (avgLoss[t-1] * 13 + loss[t]) / 14
RSI[t] = 100 - 100 / (1 + avgGain[t] / avgLoss[t])
```

- 첫 RSI 값에는 종가 15개가 필요하다.
- 상승·하락이 모두 0이면 50, 평균 하락만 0이면 100, 평균 상승만 0이면 0으로 처리한다.
- 전환 시 `calculationVersion`을 올리고 현재 단순 RSI와 Wilder RSI의 고정 데이터셋 비교표를 증적으로 남긴다.
- API와 UI를 한 버전에서 함께 전환하며 같은 `calculationVersion` 안에서 두 알고리즘을 혼용하지 않는다.

### 17.5 교차 이벤트 마커

이벤트는 직전 완성 일봉과 현재 완성 일봉을 비교하여 한 번만 생성한다.

| 이벤트 | 조건 |
|---|---|
| `MA_GOLDEN_CROSS` | 직전 `MA5 <= MA20`, 현재 `MA5 > MA20` |
| `MA_DEAD_CROSS` | 직전 `MA5 >= MA20`, 현재 `MA5 < MA20` |
| `MACD_BULLISH_CROSS` | 직전 `MACD <= Signal`, 현재 `MACD > Signal` |
| `MACD_BEARISH_CROSS` | 직전 `MACD >= Signal`, 현재 `MACD < Signal` |
| `RSI_OVERSOLD_ENTER` | 직전 `RSI > 30`, 현재 `RSI <= 30` |
| `RSI_OVERSOLD_EXIT` | 직전 `RSI <= 30`, 현재 `RSI > 30` |
| `RSI_OVERBOUGHT_ENTER` | 직전 `RSI < 70`, 현재 `RSI >= 70` |
| `RSI_OVERBOUGHT_EXIT` | 직전 `RSI >= 70`, 현재 `RSI < 70` |

- 이벤트에는 `type`, `occurredAt`, 관련 지표 값과 `calculationVersion`을 포함한다.
- 동일값이 이어지는 동안 이벤트를 반복 생성하지 않는다.
- 이벤트 마커는 해당 캔들에 표시하고 선택 시 조건과 값을 설명한다.
- 이벤트는 과거에 발생한 수학적 사실이며 미래 수익을 보장하는 매매 추천으로 표시하지 않는다.
- 기존 종합 신호 산식에는 자동으로 포함하지 않는다. 가중치 변경은 별도 검증과 버전 변경 후에만 허용한다.

### 17.6 ATR14

ATR은 방향 신호가 아니라 가격 변동성 참고값으로 사용한다.

```text
TR[t] = max(
  high[t] - low[t],
  abs(high[t] - close[t-1]),
  abs(low[t] - close[t-1])
)
initialATR = 첫 14개 TR의 산술평균
ATR[t] = (ATR[t-1] * 13 + TR[t]) / 14
atrPercent[t] = ATR[t] / close[t] * 100
```

- 이전 종가가 필요한 첫 봉에는 TR을 만들지 않는다.
- `ATR14`와 `atrPercent`를 함께 제공하여 KRW·USD 종목을 상대적으로 비교할 수 있게 한다.
- 시장별 근거 없이 낮음·보통·높음 임계값을 임의로 고정하지 않는다.
- ATR은 가격 목표나 손절 가격을 자동 추천하지 않으며 종합 신호 점수에도 포함하지 않는다.

### 17.7 목표 API 확장

기존 기술적 분석 응답은 호환 가능한 객체를 추가해 다음 정보를 제공한다. 정확한 필드 계약을 구현 전에 `03_API_SPEC.md`와 프런트 타입에 같은 변경으로 반영한다.

- `volume`: 최신 거래량, `volumeMa20`, 평균 대비 배수
- `bollingerBands`: period, multiplier, middle, upper, lower, bandwidthPercent
- `rsi.method`: `WILDER`
- `atr`: period, value, percent
- `events[]`: type, occurredAt, indicator values
- 시계열 차트 응답: 각 시점의 MA, Volume MA20, 볼린저 밴드, RSI, MACD와 ATR 값

계산 불가능한 초기 구간은 0이나 직전 값으로 채우지 않고 `null` 또는 항목 미생성으로 표현한다. 최신 요약값과 차트 시계열은 같은 입력 스냅샷과 `calculationVersion`을 사용해야 한다.

- [x] 볼린저 밴드 20·2가 고정 데이터셋의 독립 계산 결과와 허용 오차 `0.0001` 이내로 일치한다.

### 17.9 의도적으로 제외하는 기능

스토캐스틱, OBV, 일목균형표, 피보나치 도구, 분봉 영속 저장·서버 기술신호, 자동 지지·저항 탐지와 백테스트는 위 확장 목표가 통과하기 전 추가하지 않는다. 현재 1분 봉은 서버 실행 중 수신한 체결만 최대 600개 보관하며 재시작 복구나 과거 분봉 공급자 조회는 제공하지 않는다. 추가하려면 사용자 가치, 공급자 데이터 한도, 수식·초기값, API 계약과 독립 검증 기준을 먼저 명세한다.

## 18. AI 기술지표 해설 연계

Gemini는 이 문서의 계산기를 대체하지 않는다. 서버는 같은 입력 스냅샷으로 계산을 완료한 뒤 현재가·MA·Wilder RSI·MACD·볼린저 밴드·ATR·거래량과 교차 이벤트에 `I1..In` 근거 ID를 부여하고 구조화 JSON만 AI 계층에 전달한다.

- 클라이언트가 제출한 지표 값은 신뢰하지 않고 symbol·interval로 서버가 다시 조회한다.
- Gemini는 추세·모멘텀·변동성·거래량과 지표 간 충돌을 평이한 문장으로 설명한다.
- 기존 `summarySignal`은 서버 계산 결과이며 Gemini가 변경할 수 없다.
- 모델 출력의 근거 ID는 입력 ID의 부분집합이어야 한다.
- 목표주가, 수익률 예측, 직접 매수·매도 명령과 입력에 없는 수치를 금지한다.
- `STALE`·`DEMO` 입력을 허용하면 결과 첫 화면에 같은 상태와 데이터 한계를 표시한다.
- 새 완성 봉, 과거 가격 정정, `calculationVersion` 변경은 `inputHash`와 캐시 키를 변경한다.
- 상세 입력·API·프롬프트·캐시·비용·오류·인수 규칙은 `12_AI_TECHNICAL_EXPLANATION_SPEC.md`를 따른다.
